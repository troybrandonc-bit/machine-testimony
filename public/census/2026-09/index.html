Eight systems, read at pinned commits, against the Testimony Record specification

What Eight Agent Systems Record About What They Did

The first conformance census of the Testimony Record specification

Troy Clifford

Machine Testimony

Abstract

Eight agent memory and agent framework systems were assessed against the four conformance levels of the Testimony Record specification: OMEM, mem0, Graphiti, LangGraph, CrewAI, the OpenAI Agents SDK, AutoGen and Letta Code. Each was read from its public repository at a pinned commit, and every verdict cites a file and line at that commit, or a search that can be repeated against it.

Twenty requirements were derived from the published conformance levels and restated as capability questions, so that a system holding the required information in its own format is assessed on whether it holds the information rather than on whether it uses this format.

Three findings hold across every assessed system except the specification's own reference implementation. No system records who approved a gated action: four of the eight pause for human approval and none captures an approver identity, with one case left formally undetermined because the record is held in a component that could not be read. No system cleanly records that data was destroyed; where a deletion is recorded at all, the deleted content is retained alongside it. And no system publishes a scheme under which a past record can be shown not to have altered.

Keywords: AI accountability, agent memory, audit trail, human oversight, provenance, conformance assessment.

1. What was measured

The specification's reference validator answers one question: does this record conform. It cannot answer the question this census asks, because a system that has never heard of the specification emits nothing for a validator to read. Pointed at any third-party framework it would return "none" for every one of them, which is not a finding about those systems. It is an artefact of asking the wrong question.

So each requirement behind a conformance level was restated as a capability question answerable by reading a system's source. Not "does it write a belief entry with an evidence array", but "can the source a stored fact came from be recovered from the store". A system holding the information in its own shape is a translation away from conformance. A system that does not hold it cannot translate its way there at any price, and that difference is the only thing being measured.

Twenty requirements resulted, distributed across the levels as five, five, seven and three. Each subject declares what it is in the business of doing, and is assessed only on requirements that fall inside it. A vector store is not failing at approval gates. It is not an approval gate.

2. What this does not produce

There is no total, no percentage and no ordering of systems, and the tooling cannot emit one. The systems assessed here are not attempting the same job, and a number pretending otherwise would be read as a league table within a week of publication, after which nothing else would matter.

What is produced instead is a gap map: for each system, the highest level its existing capabilities already satisfy, and for the level above, exactly which facts it does not keep and where that was checked. A level counts as reached only when nothing in it is missing, so a system meeting four of five requirements shows no level at all. The per-level counts in Table 2 are reported so that this reads correctly rather than as a claim that such a system records nothing.

4. Three findings

No system records who approved

Four of the eight gate consequential actions behind a human decision, and not one of them records who made it. The OpenAI Agents SDK's approve() takes no approver argument, and the only thing named an identity in its approval path identifies the tool call rather than a person. CrewAI's request_human_input reads a line from a console and returns the text. AutoGen's ApprovalResponse requires a reason, which is more than most, and has no field for who gave it. LangGraph resumes an interrupt with an arbitrary value supplied by whoever holds the thread.

The pause is real in every case. The attribution is absent in every case. An application that approves programmatically produces a record identical to one where a person read the arguments and decided, which matters to anyone who has to evidence human oversight rather than perform it.

Letta Code is the single unsettled case and is recorded as undetermined rather than guessed. It carries a server-validated acting-user identity built to name the human who initiated a request rather than the credential that spawned the runtime, which is exactly the property this requirement asks for. Whether that identity reaches the approval record could not be established, because the record is held by a server outside the repository that was read.

No system records that data was destroyed

This is absent in five of the assessed systems and partial in two. Each has a deletion path somebody will reach for on a subject-erasure request, and the store afterwards is largely indistinguishable from one where the data never existed.

The two partial cases fail in opposite directions and are instructive for it. mem0 writes a history row recording the deletion, and writes the deleted memory's own text into that row, so content erased from the vector store remains on disk in the local history database. Letta Code records a deletion as a git commit, which is exemplary as a trace, and the content stays in history and on every mirror it was pushed to, so satisfying a real erasure request means rewriting the history that made the record trustworthy.

Almost no system can show a record did not change

The fourth conformance level is absent outright in six of the eight. Where history is preserved, it is preserved because the code path behaved, which is a weaker property than being able to demonstrate that nobody went around the code path.

Two systems are closer than they appear. LangGraph's checkpointer already links every checkpoint to its parent, which is the shape of a hash chain with identifiers where the digests should be; carrying a digest over each checkpoint and its parent would make the existing structure verifiable without altering the write path. Letta Code stores memory in a git repository, so the history is content-addressed by construction, and its post-commit push mirror is most of an external anchor already. It disables commit signing deliberately, for the sound reason that its harness-managed committer identities hold no key.

5. What each system would need

Graphiti and LangGraph each meet four of the five requirements at the first level and fail only on recording destruction, so both are one change away from a level neither was aiming at. Graphiti arrived there by being bi-temporal: a contradicted fact is stamped invalid rather than deleted, and facts point back at the episodes they were extracted from. LangGraph arrived there because resumption and time travel required it. Neither was built against this specification, which is the most useful kind of agreement there is.

mem0 and CrewAI both consolidate through a model that decides whether to keep, update or delete an existing memory. mem0 retains the previous value in a separate history database. CrewAI retains nothing, and its most tractable finding is narrow: a blocked tool call constructs a refusal reason and discards it two frames later, so the model receives a fixed string naming the tool rather than the cause.

The OpenAI Agents SDK models what was proposed more carefully than any other framework here, including a ledger recording whether each tool call executed, and leaves durability to the application embedding it. AutoGen carries the best-structured approval request of the eight, and then returns a refusal as an exit code of one, which is the shape an execution error takes, so a refusal and a crash are indistinguishable to anything counting afterwards.

6. How the instrument refuses

A census of other people's software can do real damage, and the people in it did not ask to be. Care is not a defence, because care is not auditable. The rules are therefore enforced by the tooling on every assessment, and a file breaking one of them cannot be published:

  1. Every verdict cites evidence, including a verdict of absent, which must carry at least one record of where the assessor looked and did not find it. Stating that a system lacks something without saying where you looked is an accusation wearing a measurement's clothes, and it is the failure this exercise was most likely to commit.
  2. No applicable requirement may be omitted, since a silent omission is how an unflattering result disappears.
  3. Scope cannot be an escape hatch in either direction. A subject may not mark a requirement irrelevant inside a business it claims, and may not be scored on a capability it never claimed.
  4. A requirement whose answer is held somewhere the assessor cannot read is recorded as undetermined, which blocks a level exactly as absence does. A level awarded on unchecked facts is indistinguishable from one that was verified, which makes it worse than no level at all.
  5. A verdict of partial does not clear a level.

These rules rejected the author's own work twice during preparation. The CrewAI assessment was refused for recording an absence without a repeatable search behind it, and the Letta Code assessment could not be completed until the undetermined verdict was added, because the only two answers available were both guesses.

7. Conflict of interest

OMEM is the reference implementation of the specification these questions derive from, written by the author of this census. It scores well here in the way a dictionary's author spells well, and its row should be read as carrying no evidential weight. It is included so that the questions were applied to the system that produced them before being applied to anyone else's, and so that a reader who doubts a question can open the source behind every answer to it.

Building the instrument against it first was not a formality. It produced three findings, two of them against the author. OMEM's own record export was emitting no evidence entries at all, passing the second conformance level only because an empty list satisfies the check vacuously. The first draft of the rubric scored a lawful response to an erasure request as a first-level failure, which would have marked down every system deployed in the European Union for obeying the law. And it scored a system that never resolves contradictions as failing the second level, when the specification records resolution only if it occurs and never resolving is the more conservative design. All three were corrected before any other system was assessed.

8. What a verdict is a claim about

Every verdict here is a claim about one named commit, not about a project. Not that a system does not record something, but that at a stated forty character object identifier it did not, with the file and the line. Each subject pins that identifier and the tooling refuses an abbreviation, so any reader can check out the exact tree every citation refers to.

A project that ships a missing capability tomorrow has therefore made nothing here false. The assessment was of a commit that still exists and still reads the same way. When a system changes, the response is a new assessment with a new date beside the old one, never an edit to it, which is what this specification asks of everybody else and is not a rule the census exempts itself from.

Each requirement in each assessment carries a stable identifier of the form MTC-2026-09-04-mem0-R1.5, naming the observation rather than the state of the world, so it remains valid after the behaviour it describes is changed. A published manifest fixes the digest of every assessment and of the questions they were scored against, because unchanged answers to changed questions are not the same assessment.

9. Reproduction

Everything is in the reference implementation's repository under benchmarks/census. The assessments are data, the rules that reject a bad one are code, and both are checked on every commit. 

git clone https://github.com/troybrandonc-bit/Omem
cd Omem

python3 benchmarks/census/run.py            # the report
python3 benchmarks/census/run.py --check    # validate every assessment
python3 benchmarks/census/manifest.py --check
python3 server/tests_census.py              # the refusal rules, tested

One finding is demonstrated by execution rather than by reading. Every other verdict here was reached by reading source, which is honest and weaker than it sounds, and most concern what a system does not record, which no amount of running can establish. The retention of deleted memory text is different: it asserts that something is written, and it concerns data somebody asked to have erased. It is therefore checked by running the assessed system's own storage layer, with no network, no model and no credentials. 

git clone https://github.com/mem0ai/mem0
git -C mem0 checkout 9a7924befd7026e41e445ba809370009e5e985a6
python3 benchmarks/census/verify/mem0_delete_retains_text.py --repo ./mem0

Corrections

Nothing here is self-reported and nothing is taken on trust, in either direction. Every claim cites a file and a line at a pinned commit, or a search that can be repeated against it, so a wrong verdict can be shown to be wrong rather than argued about.

If a verdict concerning your system is wrong, the correction is a pull request against its assessment file, or an email naming the requirement and where to look. A correction that lands changes the file, the report and the assessment date. There is no fee, no membership, and no requirement to use any particular software. If your system is not here and you would like it to be, the same applies: absence from this document is not a judgement, it means nobody has done the reading yet.

Notes

  1. Assessed commits, in full, are recorded in each assessment file and in the published manifest. Systems were read in the order they were obtained and no result was known in advance of reading.
  2. The specification imposes exactly one duty specific to derivation, which is that a fact a system inferred can be told apart from one it was told. Requirements were not invented to make that column look fuller, because every question here has to trace to a published conformance level for the assessment to be checkable.
  3. A dated publication establishes when an observation was made. It does not oblige anyone to credit it. The mechanism that reliably produces attribution is coordinated disclosure, in which the reporting process names the reporter, and it was not used here: these findings were published rather than sent.
