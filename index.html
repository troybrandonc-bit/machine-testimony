Machine Testimony An independent research programme

A machine can tell you what it did.
Testimony is not evidence until someone else can check it.

Machine testimony is what an automated system says about its own reasoning and actions. What it believed, what it was told, what it decided, and who allowed it. This programme studies whether that account can be verified by someone who was not there, and publishes the formats, validators and benchmarks that make the checking possible.

Why the question is not the same as the answer

The question is not new. In Machine Testimony (126 Yale L.J. 1972, 2017) Andrea Roth argued that information conveyed by a machine should carry testimonial safeguards, and worked through what those would have to be: credibility testing through design and operation protocols, disclosure and access, authentication and reliability rules, impeachment, and corroboration. This programme takes that as the brief and builds the parts of it that are engineering.

A good deal of work is going into receipts: signed, hash chained records that prove an entry has not been altered since it was written. That is worth doing, and it settles less than it appears to. A record can be cryptographically perfect and factually false, because integrity protects the entry, not the claim inside it.

The harder questions sit underneath. What did the system believe when it decided, and on what evidence. What contradicted that belief, and is the losing side still in the record. When a premise was later withdrawn, what happened to everything resting on it. When a human approved, was it a second party or the same agent under another name. Those are properties of testimony rather than of storage, and they are what this programme works on.

Four things a record can be asked to survive

Conformance levels exist so a system can be placed rather than described. Each one contains the ones beneath it, and the validator reports the highest a record actually reaches, so nobody has to take an adjective on trust.

TR-1

The record exists, is well formed, and is append-only

Every entry parses, names the specification version, has a unique id that is never reused, carries a write time, and arrives in non-decreasing order.

TR-2

Beliefs resolve to evidence, and disagreements survive

Every belief states its evidence, even when there is none. Cited evidence exists in the record, a conflict names at least two sides, and both sides are still there afterwards.

TR-3

Actions carry a verdict, and approvals carry a name

The risk class comes from outside the model proposing the action, a refused action did not execute, and every refusal records why.

TR-4

The record can be shown not to have changed

An integrity scheme is published, every integrity entry carries a digest over entries that exist, and a replay scheme names the engine and its version.

Published work

Everything here is free to implement, in any language, by anyone. It is built to be useful to people who never run our software, and each piece is designed so a stranger can check a claim instead of taking a word for it.

  • The Testimony Record

    A format for what a system believed, what contradicted it, what it tried to do and who approved it, with four conformance levels from TR-1 to TR-4 so a system can be placed rather than described.

    Specification v0.1CC BY text, MIT schema

  • The reference validator

    One file, standard library only, no network. Copy it into your own repository and run it in your own CI. A conformance claim the listener cannot check is an adjective.

    PythonZero dependencies

  • The implementations register

    Which systems emit records that pass the validator, and at what level. Entries are listed only after their records were checked, never on a claim.

    Open to any implementer

  • The commons corpus

    Regularities in human working behaviour as counts over populations, contributed by installations that opted in and holding no fact about any person. Published with a dataset card that says what it does not cover.

    CC BY 4.0Consent recorded per contribution

  • The Witness benchmark

    Six properties a memory system either has or does not: no fabrication, retraction honoured, disagreement visible, identities kept apart, conclusions die with their premises, every memory sourced.

    Runnable harness

  • The calibration benchmark

    Whether a system's confidence about a person tracks how often it turns out right, scored by Brier skill against the base rate, and reporting nothing rather than a flattering number when the record is too thin to measure.

    Runnable harness

What this is not

  • Not a certification body.

    We publish formats and the tools to check them. We do not audit anyone and we issue no certificates. The validator is public so that any conformance claim can be checked by the person hearing it, including every claim we make about ourselves.

  • One member.

    This is a research programme run by one person, not an institution with a staff. It is named for the work rather than for its own importance, and it will stay that way until the output earns otherwise.

  • One implementation, so far.

    The Testimony Record is implemented today by OMEM, which is the reference implementation and is not the specification. A format with one implementation is a proposal rather than a standard. The register exists to record the day that stops being true, and a second implementation is worth more to this work than anything else on the list.

  • It does not decide what is true.

    Nothing published here reads two accounts and concludes which one is right. The record keeps both sides, says which evidence each rests on, and leaves the judgement to a person.

Implement it, or try to break it

The most useful thing anyone can do with this work is emit a record from a system we did not write and run the validator over it. The second most useful is to show that a conformance level asks for something an honest architecture cannot give, which is a finding we would publish.

The reference implementation is OMEM, MIT licensed and self hosted.
